// -------------------- 軟體測試方法 --------------------

::Testing_Method_01::黑箱測試（Black Box Testing）的主要目標是什麼？{
    =驗證軟體功能是否符合規格需求，而不考慮程式碼的內部結構#黑箱測試將系統視為不透明的盒子，專注於輸入與輸出的行為是否符合預期。
    ~檢查程式碼的內部邏輯、路徑和結構#這是白箱測試（White Box Testing）的目標。
    ~在不確定的輸入下找到系統崩潰點#這是模糊測試（Fuzz Testing）的目標。
    ~確保新版本沒有破壞現有的功能#這是回歸測試（Regression Testing）的目標。
}

::Testing_Method_02::在軟體發布前，哪兩種測試屬於使用者驗收測試（UAT）的階段，分別由內部員工和外部真實使用者執行？{
    =Alpha Testing（內部員工）與 Beta Testing（外部使用者）#Alpha 測試在公司內部受控環境中進行，Beta 測試在發布前讓選定的真實使用者在實際環境中進行。
    ~Smoke Testing 與 Regression Testing#這是品質保證（QA）階段的測試類型，與使用者驗收無直接關係。
    ~Load Testing 與 Stress Testing#這是效能測試類型。
    ~Exploratory Testing 與 Script Testing#這是測試的執行方法。
}

::Testing_Method_03::當開發團隊發布一個新的程式建構版本（Build）時，測試團隊會快速執行一組最基本的測試案例，以確保核心功能（例如登入和啟動）能正常運作。這種測試被稱為什麼？{
    ~回歸測試（Regression Testing）#回歸測試旨在確認變更沒有破壞功能，但此處強調的是「快速」確認基本穩定性。
    ~負載測試（Load Testing）#負載測試是效能測試。
    =冒煙測試（Smoke Testing）#冒煙測試的目的是判斷新版本是否足夠穩定，可以進行更深入的測試，就像檢查電路板是否會冒煙一樣。
    ~猴子測試（Monkey Testing）#猴子測試是隨機輸入，與核心功能的穩定性檢查不同。
}

::Testing_Method_04::在軟體發生錯誤修復、功能增強或系統重構之後，必須執行哪種測試來確保新的變更沒有意外地影響或破壞既有的功能？{
    ~Alpha Testing#這是發布前的UAT階段。
    ~探索性測試（Exploratory Testing）#探索性測試是用來尋找新錯誤，而不是確認舊功能正常。
    ~模糊測試（Fuzz Testing）#模糊測試用於尋找崩潰點。
    =回歸測試（Regression Testing）#回歸測試專門用來檢驗舊功能在程式碼變更後是否仍能正常運作。
}

::Testing_Method_05::探索性測試（Exploratory Testing）和腳本測試（Script Testing）兩者之間最主要的差異是什麼？{
    =探索性測試是同時進行測試設計、執行與學習，而腳本測試是按照事先定義和文件化的步驟執行#探索性測試強調測試人員的自由發揮和即時設計，而腳本測試則要求嚴格遵循預先寫好的文件。
    ~探索性測試只能用於黑箱測試，腳本測試只能用於白箱測試#兩者都可以用於黑箱測試。
    ~腳本測試比探索性測試更能發現全新的、未預期的錯誤#探索性測試在發現全新錯誤方面通常更有效率。
    ~探索性測試必須由使用者執行，腳本測試必須由QA執行#執行者與測試方法無必然聯繫。
}

::Testing_Method_06::為了驗證系統在預期的尖峰流量或資料處理量下是否仍能保持穩定的回應時間和性能，應該執行哪種測試？{
    ~冒煙測試（Smoke Testing）#冒煙測試檢查穩定性，而非性能壓力。
    ~回歸測試（Regression Testing）#回歸測試檢查功能正確性，而非性能。
    =負載測試（Load Testing）#負載測試專門用於模擬真實環境中的預期或峰值負載，以評估系統的性能指標。
    ~Alpha Testing#這是功能性使用者驗收測試。
}

::Testing_Method_07::模糊測試（Fuzz Testing）與猴子測試（Monkey Testing）雖然都涉及隨機輸入，但它們關注的重點分別是什麼？{
    =模糊測試關注向軟體介面注入大量無效或隨機的資料以尋找崩潰；猴子測試關注使用者介面的隨機點擊和輸入，以模擬不可預期的行為#模糊測試通常是針對資料接口/協定，猴子測試通常是針對UI互動。
    ~模糊測試是白箱測試，猴子測試是黑箱測試#兩者通常都從黑箱的角度執行。
    ~模糊測試是手動執行，猴子測試是自動化執行#兩者都可以被自動化。
    ~模糊測試只適用於網頁應用，猴子測試只適用於移動應用#兩者都適用於多種應用類型。
}

::Testing_Method_08::在一個持續整合（CI）流程中，為了在最短時間內確保新提交的程式碼品質可以繼續開發，測試人員最合理的做法是將哪兩種測試類型結合起來？{
    ~負載測試與模糊測試#這兩種測試耗時且目標不同。
    =冒煙測試與回歸測試#先用冒煙測試（Smoke Testing）快速確認基本功能穩定性，再用自動化的回歸測試（Regression Testing）確保新變更未破壞既有功能。
    ~Alpha 測試與 Beta 測試#這是在發布階段進行的 UAT。
    ~探索性測試與腳本測試#這是執行方法上的選擇，不是 CI 流程中效率最高的穩定性組合。
}

::Testing_Method_09::當一個產品準備進入 Beta 測試階段時，測試團隊的主要目的是什麼？{
    ~向外界證明產品程式碼的內部邏輯是無瑕疵的#這是白箱測試的目標。
    =在真實的使用情境和環境中，由目標使用者發現產品潛在的可用性問題和未被發現的缺陷#Beta 測試是讓外部使用者在實際環境中進行最終的驗收和品質確認。
    ~對產品執行極端的壓力測試直到系統崩潰#這是壓力測試的目標。
    ~確保所有現有功能都沒有被新的程式碼破壞#這是回歸測試的目標。
}

::Testing_Method_10::以下哪一個測試案例設計技術**不屬於**黑箱測試方法？{
    ~邊界值分析法（Boundary Value Analysis）#這是黑箱測試中最常用的技術之一。
    ~等價類劃分法（Equivalence Partitioning）#這是黑箱測試中最常用的技術之一。
    =程式碼覆蓋率分析（Code Coverage Analysis）#程式碼覆蓋率需要查看內部結構和程式碼，屬於白箱測試的範疇。
    ~決策表測試（Decision Table Testing）#這是基於業務規則和規格的黑箱測試技術。
}
