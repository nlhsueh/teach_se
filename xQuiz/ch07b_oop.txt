// 題目 1: 一般化原則 (Generalization Principle)
::一般化原則::在物件導向設計中，「一般化原則 (Generalization Principle)」的主要應用是？{
~透過繼承將子類別與父類別完全隔離。
=使用繼承來抽象化和重用共同的行為與屬性，將通用的功能放在父類別中。
~鼓勵在類別中重複撰寫相同的程式碼。
~只用於定義物件的資料庫連接。
}

// 題目 2: Liskov 取代原則 (Liskov Substitution Principle, LSP)
::Liskov 取代原則::「Liskov 取代原則 (LSP)」的核心要求是什麼？{
~子類別可以隨意修改父類別的介面和行為。
=程式中所有父類別出現的地方，都可以被其子類別替換，而不影響程式的正確性。
~子類別必須比父類別擁有更多的公開方法。
~所有類別必須是最終 (final) 且不能被繼承。
}

// 題目 3: 善用包含/委託 (Composition/Delegation over Inheritance)
::包含與委託::物件導向設計中，提倡「善用包含或委託 (Composition/Delegation)」而非繼承 (Inheritance) 的主要原因是什麼？{
~繼承會導致程式碼更難編譯。
=繼承會形成緊密耦合，而包含和委託提供更大的彈性與更鬆散的耦合。
~委託只能用於處理私有方法。
~繼承無法重用程式碼。
}

// 題目 4: 介面隔離原則 (Interface Segregation Principle, ISP) 與介面污染 (Interface Pollution)
::介面污染::「介面污染 (Interface Pollution)」是指什麼狀況？這違反了哪個 SOLID 原則？{
~一個類別實作了太多方法。
~多個無關的介面被合併成一個。
=介面中包含了客戶端 (Client) 不需要的方法，迫使客戶端實作不相關的職責（違反了 ISP）。
~所有的介面都只包含一個方法。
}

// 題目 5: 善用介面 (Favouring Interfaces)
::善用介面::在物件導向設計中，「善用介面 (Favouring Interfaces)」相較於實作類別 (Concrete Classes) 的優勢是什麼？{
~介面可以直接實例化 (Instantiate) 物件。
=介面定義了契約 (Contract)，使類別的實作可以被抽換，提高了彈性和低耦合。
~介面可以包含資料欄位和完整的方法實作。
~實作類別無法被繼承。
}

// 題目 6: 相依反轉原則 (Dependency Inversion Principle, DIP) 的目標
::相依反轉::「相依反轉原則 (Dependency Inversion Principle, DIP)」主張設計者應如何處理模組間的依賴關係？{
~高層模組應直接依賴低層模組的細節實作。
=高層模組與低層模組應同時依賴於**抽象 (Abstraction)**（如介面或抽象類別）。
~只允許使用靜態方法來傳遞資料。
~消除所有的抽象層。
}

// 題目 7: 相依反轉原則 (DIP) 的實踐
::DIP 實踐::下列哪種做法是實踐「相依反轉原則 (DIP)」的常見方式？{
~直接在類別內部使用 `new` 關鍵字創建其所有依賴的物件。
~讓抽象介面依賴於具體的實作類別。
=讓高層類別透過建構子 (Constructor) 或設定方法 (Setter) 接收其抽象介賴 (Dependency Injection)。
~將所有邏輯放入一個單一的靜態 (static) 類別中。
}

// 題目 8: 控制反轉 (Inversion of Control, IoC) 的概念
::控制反轉::「控制反轉 (Inversion of Control, IoC)」的概念是什麼？{
~控制流程由應用程式碼本身完全控制。
=將物件的創建和生命週期管理權**從應用程式碼轉移**給一個外部容器或框架。
~只允許物件在自身的建構子中進行初始化。
~所有的程式碼都必須以同步 (Synchronous) 方式執行。
}

// 題目 9: 介面隔離原則 (Interface Segregation Principle, ISP)
::ISP::「介面隔離原則 (ISP)」主張：{
~一個系統應該只有一個大型介面。
=客戶端不應該被迫依賴於它不使用的方法或介面。
~所有方法都應該實作成私有 (private)。
~一個類別只能實作一個介面。
}

// 題目 10: 繼承層次過深的問題 (一般化原則的反思)
::一般化反思::如果物件導向設計中，類別的繼承層次變得過深（例如超過五層），可能會帶來什麼主要問題？{
~提高程式碼的執行速度。
=增加系統的複雜度，使程式碼的行為追蹤困難，且違反 LSP 的風險增高。
~自動實現高內聚低耦合。
~鼓勵使用委託模式。
}
