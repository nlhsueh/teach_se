// 題目 1: 瀑布模型 (Waterfall Model)
::瀑布模型::瀑布模型 (Waterfall Model) 的主要限制或缺點是什麼？{
~它過於強調重複與回饋。
=它要求在專案早期階段就完成所有需求的定義，難以適應需求變更。
~它在每個階段結束時沒有明確的交付物 (deliverables)。
~它不適用於硬體和軟體整合的專案。
}

// 題目 2: 增量式開發 (Incremental Development)
::增量式開發::增量式開發 (Incremental Development) 模型的主要特點是？{
~每個階段都必須在下一個階段開始前完全凍結需求。
~只適用於小型且單一功能的專案。
=將軟體切割成多個版本或增量，每個增量都加入新的功能。
~強調專案必須在短時間內一次性完成所有功能。
}

// 題目 3: 疊代與增量式開發 (Iterative and Incremental)
::疊代與增量::相較於純粹的增量式開發，疊代與增量式開發 (Iterative and Incremental) 更強調哪個方面？{
~每個增量必須由不同的團隊開發。
~在第一個增量中交付所有核心功能。
=透過多次迴圈 (Iteration) 不斷地精進與重構已開發的功能。
~完全消除軟體專案中的測試活動。
}

// 題目 4: 需求分析活動
::需求分析::在軟體開發生命週期中，「需求分析 (Requirements Analysis)」活動的主要產出是什麼？{
~系統的程式碼與資料庫結構。
=一份定義系統應提供服務和約束條件的需求規格文件。
~詳細的測試計畫和測試用例。
~軟體操作手冊。
}

// 題目 5: 架構設計活動
::架構設計::「架構設計 (Architectural Design)」活動在軟體開發中的主要目標是什麼？{
~撰寫所有低階的程式碼邏輯。
~確定最終使用者介面的視覺風格。
=定義系統的高階結構、組件及其之間的關係。
~處理系統的緊急錯誤和漏洞修復。
}

// 題目 6: 變更處理 (Change Management)
::變更處理::在軟體開發過程中，處理變更 (Change Management) 的重要性在於？{
~完全拒絕任何需求變更以維持時程。
=建立一個正式流程來評估、批准、追蹤和控制對軟體基線的修改。
~確保變更只由專案經理決定。
~變更處理是測試階段的專門活動。
}

// 題目 7: 雛形開發 (Prototyping) 的應用
::雛形應用::「雛形開發 (Prototyping)」技術最常應用於軟體開發生命週期的哪個階段？{
~最終的系統驗收與交付。
=需求探索與驗證，特別是在需求不明確時。
~系統的詳細實作和程式撰寫。
~軟體發布後的長期維護。
}

// 題目 8: CMMI 概念
::CMMI::CMMI (Capability Maturity Model Integration) 是一種用來衡量什麼的框架？{
~單一軟體產品的效能和速度。
=組織在軟體開發與維護方面「過程成熟度」和「能力」。
~軟體工程師的個人編程技能水平。
~硬體與軟體整合的程度。
}

// 題目 9: CMMI 成熟度等級
::CMMI 等級::在 CMMI 成熟度模型中，Level 2 的「已管理 (Managed)」等級主要強調哪項活動的實施？{
~組織範圍的持續過程改進。
=專案層級的需求管理、規劃和品質保證。
~量化管理和過程控制。
~隨機和雜亂無章的開發方式。
}

// 題目 10: 細節設計與實作
::細節設計::在軟體生命週期中，「細節設計 (Detailed Design)」與「實作 (Implementation)」階段的關係最接近於？{
~細節設計是完全獨立於實作之外的活動。
=細節設計將架構組件轉換為可編程的模組規格，隨後在實作階段撰寫程式碼。
~實作是處理系統的非功能性需求，而細節設計處理功能性需求。
~兩者都只是在軟體發布後才進行。
}
