// -------------------- 軟體測試基礎原則 --------------------

::Testing_Principle_01::「錯了就是有臭蟲，沒錯並不代表沒有臭蟲」這個原則對測試工作的核心啟示是什麼？{
    ~測試的成功取決於找到的臭蟲數量#測試目標是找出臭蟲，但其核心意義在於無法證明程式的完美性。
    =測試可以證明臭蟲的存在，但無法證明臭蟲的完全不存在#這是該原則的標準表述，測試只能揭示缺陷（Presence of Defects），不能證明沒有缺陷（Absence of Defects）。
    ~所有的軟體錯誤最終都會被修復#這與「並不是所有的錯誤都會被修復」原則相悖。
    ~我們必須對每個輸入都進行窮盡測試#這與「窮盡測試是不可行的」原則相悖。
}

::Testing_Principle_02::測試人員面對「窮盡測試是不可行的」這一事實，應如何選擇最實際的工作方法？{
    ~嘗試在無限的時間內完成所有可能的測試組合#窮盡測試不可行，且時間有限。
    =基於「軟體測試是一種風險管理的工作」原則，優先測試高風險區域#由於時間、資源和窮盡測試的限制，測試必須是基於風險的選擇性工作。
    ~只專注於測試最容易找到臭蟲的功能#雖然有助於發現問題，但忽略了風險更高的區域。
    ~完全依賴自動化測試來涵蓋所有可能性#自動化測試也不能實現窮盡測試。
}

::Testing_Principle_03::當測試人員持續使用同一套測試案例，卻發現越來越難找到新的臭蟲時，最可能發生了哪個原則中描述的現象？{
    ~即早測試#與測試的時機無關。
    =殺蟲劑效應（Pesticide Paradox）#當測試案例重複使用時，系統會對其產生「免疫力」，需要審查和更新測試案例才能找到新的臭蟲。
    ~錯誤總是躲在角落#錯誤一直存在，但這個原則描述的是測試方法的無效性。
    ~漸進式的測試#這是一種測試方法，與此現象無關。
}

::Testing_Principle_04::如果一個應用程式的核心交易模組在過去六個月內發現了 80% 的嚴重錯誤，根據測試原則，測試經理應如何調整測試資源？{
    =根據「錯誤總是躲在角落」的原則，將更多的測試資源和時間集中在這個模組#此原則（ Defects Clustering，缺陷群聚）指出大部分缺陷集中在少數模組中，應優先集中資源。
    ~為了公平起見，平均分配資源給所有模組#這忽略了缺陷群聚的現實，不是風險管理的方法。
    ~立即停止該模組的測試，因為它已經有足夠的測試#忽略了高風險區域需要持續關注的需求。
    ~利用「殺蟲劑效應」的原理，完全不改變測試案例#殺蟲劑效應要求改變測試案例，而非保持不變。
}

::Testing_Principle_05::以下哪項最佳地體現了「即早測試」（Early Testing）的原則？{
    ~在產品發布前一週開始執行壓力測試#這不是即早測試，壓力測試應在系統開發完成後進行。
    =在軟體生命週期的需求分析或設計階段就開始進行靜態測試或同行審查#即早測試的目標是在開發週期的初期發現並修復缺陷，此時的成本最低。
    ~一旦發現臭蟲，就立即通知開發團隊#這是錯誤回報的流程，與測試的時機無關。
    ~專案結束後，將測試報告歸檔#這是收尾工作。
}

::Testing_Principle_07::在專案進度緊張且資源有限的情況下，測試團隊發現了兩個臭蟲：一個是影響核心功能的嚴重錯誤，另一個是介面上的小錯誤。根據測試原則，團隊應優先處理哪個問題？{
    ~介面上的小錯誤，因為它比較容易修復#這忽略了風險管理的重要性。
    =核心功能的嚴重錯誤，因為「軟體測試是一種風險管理的工作」#測試的優先順序應根據風險和業務影響來決定，嚴重錯誤的風險最高。
    ~將兩個錯誤都擱置，直到專案結束#這違反了即早測試和風險管理的原則。
    ~將此問題交給開發團隊來自行判斷#測試團隊應該基於風險管理提供建議。
}

::Testing_Principle_09::當我們說「窮盡測試是不可行的」，這實際上是要求測試人員採取什麼行動？{
    =定義合理的測試範圍（Scope）和測試案例（Test Cases）來達成風險最小化#由於無法測試所有可能性，測試必須有重點、有範圍地進行，以最小化風險。
    ~忽略所有負面測試（Negative Testing）#負面測試是測試策略的重要組成部分。
    ~只進行單元測試，忽略系統整合測試#不同層次的測試都是必要的。
    ~使用隨機測試（Fuzz Testing）來代替所有計劃的測試#隨機測試只能作為補充，無法代替計劃性的測試。
}

::Testing_Principle_10::測試團隊發現，每次執行同一個測試套件時，發現的新錯誤數量都在急劇下降。根據「殺蟲劑效應」原理，為了提高測試效率，他們接下來最應該做什麼？{
    ~停止測試，因為系統可能已經完美#這違反了「沒錯並不代表沒有臭蟲」的原則。
    ~只進行回歸測試，以確保現有功能正常運作#回歸測試不能找到新的錯誤。
    =修改現有的測試案例並建立新的測試，以測試系統的不同部分或新的測試情境#殺蟲劑效應要求測試案例的變異和更新，這是解決此問題的關鍵。
    ~根據「並不是所有的錯誤都會被修復」原則，忽略現有的下降趨勢#此原則與處理新錯誤的發現效率無關。
}
