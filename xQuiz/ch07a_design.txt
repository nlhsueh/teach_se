// 題目 1: 模組化原則 (Modularity)
::模組化原則::軟體設計中的「模組化原則 (Modularity)」主要目標是什麼？{
~將所有程式碼集中在一個檔案中以便於管理。
=將系統分解為一系列獨立、可替換的組件，以降低複雜度和提高可維護性。
~確保每個組件都能與系統中的所有其他組件直接溝通。
~只適用於硬體系統的設計。
}

// 題目 2: 低耦合 (Low Coupling) 原則
::低耦合::「低耦合 (Low Coupling)」原則要求軟體模組之間應如何設計？{
~每個模組必須知道所有其他模組的內部實作細節。
=模組之間的依賴關係應盡可能地少且鬆散，減少一個模組變動對其他模組的影響。
~所有模組必須共享相同的全域變數。
~只允許模組透過繼承來傳遞數據。
}

// 題目 3: 高內聚 (High Cohesion) 原則
::高內聚::「高內聚 (High Cohesion)」原則要求軟體模組的內部應如何設計？{
~一個模組應包含多個不相關的功能。
~模組的功能必須被劃分到盡可能多的檔案中。
=模組內的所有元素（屬性與方法）應專注於完成一個單一、定義明確的目標或職責。
~模組內部的程式碼應該是隨機排列的。
}

// 題目 4: 不重複原則 (DRY - Don't Repeat Yourself)
::DRY 原則::「不重複原則 (DRY - Don't Repeat Yourself)」的主要含義是？{
~在任何情況下都不能使用迴圈。
=系統中的每一條知識或邏輯都應該在一個、且是唯一的一個地方明確地表示。
~只允許在程式碼中重複使用變數名稱。
~避免所有的程式碼註釋。
}

// 題目 5: 資訊隱藏原則 (Information Hiding)
::資訊隱藏::「資訊隱藏 (Information Hiding)」原則強調設計者應如何處理模組的內部實作細節？{
~將所有實作細節公開，以便於其他模組存取。
=將模組的實作細節（如資料結構或演算法）隱藏在介面之後，防止外部模組直接依賴它們。
~只有在系統出現錯誤時才隱藏資訊。
~所有程式碼都必須在單一的公開 API 中。
}

// 題目 6: Don't Talk to Strangers (迪米特法則/Law of Demeter)
::Law of Demeter::「Don't Talk to Strangers (迪米特法則)」這一設計原則告誡開發者應如何處理物件間的互動？{
~一個物件應該可以直接呼叫遠程伺服器上的所有方法。
~物件可以透過巢狀呼叫 (Chaining Calls) 與任何深度層級的物件互動。
=一個物件應只與其直接朋友（如自身的組件、傳入的參數等）互動，減少對外部結構的依賴。
~完全禁止一個物件呼叫另一個物件的方法。
}

// 題目 7: 開放-封閉原則 (Open-Closed Principle, OCP)
::OCP::「開放-封閉原則 (Open-Closed Principle, OCP)」主張軟體實體（如類別、模組、函數等）應該是：{
~對修改 (Modification) 開放，對擴展 (Extension) 封閉。
=對**擴展 (Extension) 開放**，對**修改 (Modification) 封閉**。
~對所有形式的擴展和修改都封閉。
~對所有形式的擴展和修改都開放。
}

// 題目 8: 受保護的變異 (Protected Variation, PV)
::Protected Variation::「受保護的變異 (Protected Variation, PV)」原則與下列哪個概念最為相關？{
~將所有變量標記為公開 (public)。
~在程式碼中創建多個相似的變數。
=使用介面、抽象類別或多型 (Polymorphism) 等機制，將預期會變化的點與不變的程式碼隔離開來。
~確保所有的程式碼都使用單一的靜態 (static) 方法。
}
