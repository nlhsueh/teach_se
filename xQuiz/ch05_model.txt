// 題目 1: 使用案例圖 (Use Case Diagram) 的用途
::Use Case 圖用途::在需求工程階段，使用「使用案例圖 (Use Case Diagram)」的主要目的是什麼？{
~展示系統內部的靜態資料結構。
=定義系統的邊界、外部參與者 (Actors) 以及系統提供的高階功能 (Use Cases)。
~詳細描述物件之間訊息傳遞的時序。
~模擬業務流程中的並行活動與決策點。
}

// 題目 2: 類別圖 (Class Diagram) 在需求分析的應用
::類別圖需求分析::在需求分析初期使用「類別圖 (Class Diagram)」的主要目的是？{
=建立領域模型 (Domain Model)，識別系統所關聯的重要概念性實體、屬性及其關係。
~詳細規劃軟體類別的繼承與多型 (Polymorphism)。
~驗證系統的性能需求。
~模擬外部系統如何使用特定的 API。
}

// 題目 3: 靜態與動態模型
::UML 模型類型::在 UML 圖表中，哪種圖表主要用於描述系統的「靜態結構 (Static Structure)」？{
~活動圖 (Activity Diagram)。
~循序圖 (Sequence Diagram)。
=類別圖 (Class Diagram)。
~使用案例圖 (Use Case Diagram)。
}

// 題目 4: 循序圖 (Sequence Diagram) 的用途
::循序圖用途::「循序圖 (Sequence Diagram)」在需求工程中是用來表達什麼？{
~系統的部署環境和硬體配置。
=在特定情境 (Scenario) 下，物件或參與者之間訊息交換的**時間順序**。
~系統的狀態機轉換邏輯。
~資料在系統元件間的持續性流動。
}

// 題目 5: 活動圖 (Activity Diagram) 的用途
::活動圖用途::「活動圖 (Activity Diagram)」在需求工程中最適合用來做什麼？{
~展示系統的抽象類別與介面。
~定義使用者和外部系統的權限。
=模擬複雜的**業務流程 (Business Workflow)** 或單一使用案例的步驟執行流程。
~記錄系統的錯誤處理代碼。
}

// 6. 活動圖中的 Fork/Join
::活動圖分岔::在 UML 活動圖中，使用「分岔與匯合 (Fork and Join)」符號的主要目的是？{
~標記流程中的主要決策點。
=表示流程中的活動可以**並行 (Concurrent)** 執行，以及它們何時需要同步。
~定義迴圈或迭代的開始與結束。
~標記系統的起點和終點。
}

// 題目 7: 類別圖與功能性/非功能性需求
::圖表與需求種類::相較於活動圖和循序圖，「類別圖 (Class Diagram)」最直接有助於釐清以下哪一類需求？{
~性能 (Performance) 需求。
=功能性 (Functional) 需求中的資料與結構。
~可用性 (Usability) 需求。
~可靠性 (Reliability) 需求。
}

// 題目 8: 從使用案例到循序圖
::圖表間的關係::通常，「循序圖 (Sequence Diagram)」是針對哪種 UML 模型的特定執行路徑或情境所繪製的？{
~狀態圖 (State Machine Diagram)。
=使用案例 (Use Case)。
~部署圖 (Deployment Diagram)。
~元件圖 (Component Diagram)。
}

// 題目 9: UML 在溝通上的價值
::UML 溝通價值::在需求工程中使用 UML 圖表相較於純文字描述的最大優勢是什麼？{
~完全取代所有文字描述，節省撰寫時間。
=提供視覺化的、標準化的模型，有助於開發者與非技術的利害關係人之間**溝通和理解**。
~UML 圖表能夠自動生成完整的程式碼。
~只適用於軟體開發初期，後期沒有價值。
}

// 題目 10: 循序圖中的生命線
::循序圖生命線::在循序圖 (Sequence Diagram) 中，「生命線 (Lifeline)」代表什麼？{
~資料庫中的一條記錄。
~系統的運行時間。
=在該情境中互動的**物件 (Object)** 或**參與者 (Actor)**。
~流程中的一個決策點。
}
