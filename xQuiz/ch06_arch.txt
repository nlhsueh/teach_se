// 題目 1: 軟體架構的角色
::架構師角色::在軟體開發過程中，系統架構 (System Architecture) 的主要職責是什麼？{
~撰寫所有高階程式碼和單元測試。
=在系統實現前，定義系統的高階結構、組件及其連接器，並作為分析系統行為的基礎。
~僅處理使用者介面 (UI) 的視覺設計和使用者體驗 (UX)。
~負責在系統上線後修復所有的緊急錯誤。
}

// 題目 2: MVC (Model-View-Controller) 模式
::MVC 模式::MVC 架構模式的核心目標是？{
~將所有功能集中到一個大型的控制器 (Controller) 組件中。
=將應用程式分離為三個相互獨立的部分：資料模型、使用者介面與控制邏輯。
~確保資料庫存取操作必須在視圖 (View) 層完成。
~只適用於硬體控制系統。
}

// 題目 3: 分層架構 (Layered Architecture)
::分層架構::分層架構 (Layered Architecture) 的主要優點是？{
~允許每層都可以自由地直接呼叫系統中的任何其他層。
=透過嚴格的單向依賴關係，使系統的職責分離 (Separation of Concerns)，易於修改和維護。
~它只適用於簡單的桌面應用程式。
~它強制要求所有數據處理都在表示層 (Presentation Layer) 完成。
}

// 題目 4: 儲存庫模式 (Repository Pattern)
::儲存庫模式::在常見的軟體設計中，「儲存庫模式 (Repository Pattern)」的主要目的是什麼？{
~專門用於處理使用者介面 (UI) 的事件。
~定義系統的業務流程。
=將領域模型 (Domain Model) 與數據存取邏輯（如資料庫操作）分離，提供一個一致的資料存取抽象。
~管理系統中所有並行線程的同步。
}

// 題目 5: 客戶-伺服器模式 (Client-Server Pattern)
::客戶伺服器::客戶-伺服器模式 (Client-Server Pattern) 的核心概念是？{
~所有的處理邏輯都必須在客戶端 (Client) 完成。
~客戶端和伺服器必須使用相同的作業系統。
=將功能分佈在兩個不同的實體上：一個提供服務的伺服器，和一個使用服務的客戶端。
~它是一種純粹的靜態資料結構模型。
}

// 題目 6: 管道與過濾器模式 (Pipe-and-Filter Pattern)
::管道過濾器::管道與過濾器模式 (Pipe-and-Filter Pattern) 的主要特點是什麼？{
~所有的組件都必須共享一個單一的中央資料儲存庫。
=將系統分解為一系列獨立的處理組件 (Filter)，它們透過數據流管道 (Pipe) 串聯起來，每個組件執行一次轉換。
~它只用於 Web 瀏覽器的設計。
~組件之間可以任意地雙向傳遞控制和數據。
}

// 題目 7: 微服務架構 (Microservice Architecture)
::微服務::微服務架構 (Microservice Architecture) 相較於單體 (Monolithic) 架構，其主要優點之一是？{
~極大地減少了網路延遲和通訊開銷。
=允許開發團隊獨立部署、擴展和使用不同的技術棧來開發每個服務。
~確保系統只需要一個單一、集中的資料庫。
~完全消除了軟體維護的需求。
}

// 題目 8: 架構與非功能性需求
::架構與 NFR::選擇一個適當的軟體架構模式，對軟體開發的哪個方面影響最大？{
~需求規格文件 (SRS) 的篇幅。
~單元測試的覆蓋率。
=非功能性需求 (NFR)，例如性能、安全性、可擴展性和可維護性。
~軟體開發團隊的人數。
}
