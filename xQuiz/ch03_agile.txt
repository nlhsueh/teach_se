// 題目 2: 敏捷與傳統的差異
::敏捷與傳統::敏捷方法與傳統的重量級 (Heavyweight) 方法（如瀑布模型）最主要的區別在於：{
~敏捷完全不進行任何規劃。
=敏捷強調對變更的快速回應，並以疊代與增量方式交付功能。
~傳統方法只適用於小型團隊。
~敏捷只適用於硬體開發專案。
}

// 題目 3: 極限編程 (Extreme Programming, XP) 的最佳實踐
::XP 實踐::下列哪一項是極限編程 (XP) 強調的核心「最佳實踐」之一？{
~延遲所有的測試活動直到專案結束。
=持續整合 (Continuous Integration) 與短週期發布。
~要求開發人員單獨工作以提高效率。
~避免任何客戶或使用者參與開發過程。
}

// 題目 4: XP 的結對編程 (Pair Programming)
::結對編程::在極限編程 (XP) 中，「結對編程 (Pair Programming)」的主要好處是什麼？{
~加快打字速度。
~只適用於初級程式設計師的培訓。
=提高程式碼品質、即時審查、知識共享和減少錯誤。
~避免所有的程式碼註釋。
}

// 題目 6: Scrum 方法的角色 (Scrum Master)
::Scrum 角色 2::Scrum Master 的主要職責是什麼？{
~負責撰寫所有的程式碼。
~決定產品的最終功能和發布日期。

~代替開發團隊與客戶進行所有的溝通。
}

// 題目 8: Scrum 每日站立會議
::每日站立會議::Scrum 的每日站立會議 (Daily Scrum/Stand-up) 應在哪裡舉行？{
~持續一小時以上的深度討論。
~作為解決所有技術問題的主要場所。
=固定時間和地點，通常不超過 15 分鐘，用於同步團隊進度與計畫。
~只在產品負責人生病時才舉行。
}

// 題目 9: TDD (測試驅動開發)
::TDD::測試驅動開發 (Test-Driven Development, TDD) 是 XP 的一個實踐，其基本步驟順序是什麼？{
~撰寫程式碼 -> 執行測試 -> 撰寫測試。
~設計架構 -> 撰寫程式碼 -> 撰寫測試。
=先撰寫失敗的單元測試 -> 撰寫最少量的程式碼使其通過 -> 重構程式碼。
~先重構程式碼 -> 撰寫單元測試 -> 撰寫程式碼。
}

// 題目 10: 敏捷的回饋機制
::敏捷回饋::在敏捷開發流程中，哪個會議是為了向利害關係人 (Stakeholders) 展示已完成的工作，並收集其回饋的正式場合？{
~衝刺規劃會議 (Sprint Planning)。
~每日站立會議 (Daily Stand-up)。

~衝刺回顧會議 (Sprint Retrospective)。
}
