// -------------------- 白箱測試涵蓋率技術 --------------------

::WhiteBox_Coverage_01::在白箱測試的幾種基本涵蓋率中，哪一種涵蓋率的強度最低，即使達到 100%，也無法保證執行到程式碼中的所有分支路徑？{
    =Statement Coverage (敘述涵蓋)#敘述涵蓋只要求每行可執行程式碼被執行一次，它無法偵測到決策判斷中未被執行的分支（例如 `if/else` 中的某一個分支被跳過）。
    ~Branch Coverage (分支涵蓋)#分支涵蓋要求每個決策的 True/False 分支都被執行，比敘述涵蓋強。
    ~Condition Coverage (條件涵蓋)#條件涵蓋要求每個布林子條件都取到 True/False，比敘述涵蓋強。
    ~Path Coverage (路徑涵蓋)#路徑涵蓋要求所有可能路徑都被執行，強度最高。
}

::WhiteBox_Coverage_02::「路徑涵蓋」（Path Coverage）要求測試執行程式碼中所有可能的路徑組合。在實務上，這個目標為什麼幾乎是不可實現的？{
    ~路徑涵蓋不需要白箱測試工具的輔助#路徑分析工具是需要的。
    =因為程式碼中的迴圈（Loops）會產生理論上無限多種不同的路徑組合#迴圈的次數變化會產生龐大的路徑數量，使窮盡路徑涵蓋成為不可行（Impossible）。
    ~路徑涵蓋比敘述涵蓋更容易達成 100%#路徑涵蓋的強度遠高於敘述涵蓋。
    ~路徑涵蓋與黑箱測試的技術相衝突#路徑涵蓋是純粹的白箱測試技術。
}

::WhiteBox_Coverage_03::以下哪種涵蓋率的達成，能夠保證 100% 敘述涵蓋（Statement Coverage）也被達成？{
    =Branch Coverage (分支涵蓋)#如果一個程式中的所有分支都被執行，則所有敘述（程式碼行）也必然被執行。
    ~Condition Coverage (條件涵蓋)#如前所述，100% CC 不一定保證執行到所有分支，因此不一定保證執行到所有敘述。
    ~Modified Condition/Decision Coverage (MC/DC)#MC/DC 的強度高於分支涵蓋，但題目要求的是最低的保證。
    ~所有以上皆非#分支涵蓋確實能保證敘述涵蓋。
}

::WhiteBox_Coverage_04::如果一個布林決策表達式未使用短路運算（Non-short-circuit），達成 100% 條件涵蓋（Condition Coverage, CC）的測試集是否保證達成 100% 分支涵蓋（Branch Coverage, BC）？{
    ~是，因為 CC 的強度總是大於 BC#CC 和 BC 的關係並非簡單的包含關係。
    ~是，因為所有子條件都為 True 和 False 必然執行了所有路徑#這忽略了邏輯運算元的最終結果。
    =否，因為 CC 可能無法強迫執行決策判斷的真分支或假分支#如 $IF (A \text{ AND } B)$ 的範例，CC 可能導致總體決策結果（Decision Result）始終相同，而未能涵蓋所有分支。
    ~否，但 100% BC 必然保證 100% CC#這是錯誤的，100% BC 不保證 100% CC。
}

::WhiteBox_Coverage_07::以下關於白箱測試涵蓋率的陳述，哪一個是**錯誤的**？{
    ~達到 100% 分支涵蓋，必然也達成了 100% 敘述涵蓋#正確。
    ~路徑涵蓋是所有涵蓋標準中最嚴格的#正確。
    =達成 100% 敘述涵蓋，可以證明程式碼中沒有邏輯錯誤#錯誤。敘述涵蓋強度太低，無法保證無邏輯錯誤，例如遺漏的分支或錯誤的條件。
    ~程式碼中有未被執行的敘述，表示敘述涵蓋率低於 100%#正確。
}

::WhiteBox_Coverage_08::如果一個測試集的目的是要驗證控制流圖（Control Flow Graph）中的所有邊緣（Edges）都被執行過，那麼這個測試集追求的涵蓋標準是什麼？{
    ~Statement Coverage (敘述涵蓋)#敘述涵蓋關注節點（Nodes）。
    =Branch Coverage (分支涵蓋)#分支涵蓋或決策涵蓋（Decision Coverage）要求所有控制流圖中的邊緣（代表分支的走向）都被至少執行一次。
    ~Condition Coverage (條件涵蓋)#條件涵蓋關注布林表達式內部的子條件。
    ~Path Coverage (路徑涵蓋)#路徑涵蓋關注邊緣的組合。
}
