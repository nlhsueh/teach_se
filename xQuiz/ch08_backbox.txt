::BlackBox_Advanced_01::等價分割（Equivalence Partitioning）的主要目的與優點是什麼？{
    =將輸入資料劃分為有限數量的分區，並用每個分區的代表值來測試，從而顯著減少測試案例數量#等價分割的目標是找到一組具有相同行為邏輯的輸入，僅測試其中一個代表值。
    ~專注於測試輸入範圍的極端值和邊緣#這是邊界值分析（Boundary Value Analysis）的目的。
    ~確保所有可能的輸入組合都至少被測試過一次#這會導致窮盡測試。
    ~驗證系統的性能和穩定性#這是性能測試的目的。
}

::BlackBox_Advanced_02::在邊界值分析（Boundary Value Analysis, BVA）的三點測試策略中，對於一個有效的範圍 [min, max]，應測試哪些關鍵值？{
    =min-1, min, min+1, max-1, max, max+1 等邊緣及其附近的值#三點策略通常指對最大值（max）、最大值鄰近（max-1）和無效值（max+1）等邊界進行測試。
    ~只測試範圍內的中間值#中間值測試無法有效發現邊界錯誤。
    ~只測試 max 和 min#只測試兩個點可能錯過邊緣條件的程式設計錯誤。
    ~所有可能的分區代表值#這是等價分割的目的。
}

::BlackBox_Advanced_03::「弱涵蓋」（Weak Equivalence Coverage）與「強涵蓋」（Strong Equivalence Coverage）在等價分割中的主要區別是什麼？{
    =弱涵蓋只要求測試案例涵蓋每個等價區的代表值；強涵蓋則要求測試案例涵蓋所有輸入變數之間可能組合的等價區#弱涵蓋只關注單一變數的有效性，而強涵蓋則關注多個變數的交互組合。
    ~弱涵蓋只測試有效區，強涵蓋只測試無效區#兩者都應測試有效區和無效區。
    ~弱涵蓋測試案例較多，強涵蓋測試案例較少#通常強涵蓋會產生更多的測試案例。
    ~兩者與等價分割無關，是白箱測試的概念#兩者都是黑箱測試中用於量化測試強度的技術。
}

::BlackBox_Advanced_04::「全成對測試」（All-Pairs Testing / Pairwise Testing）是一種有效的測試案例縮減技術，其核心原理是什麼？{
    ~確保所有可能的三個輸入變數組合都被測試#這是三元組（3-wise）測試。
    =假設多數缺陷是由單個或一對（兩個）輸入變數的特定組合所引起的，因此要求所有輸入參數的每一對組合都被至少測試一次#全成對測試基於「兩個變數的組合最可能導致錯誤」的經驗法則，大大減少了測試案例數量。
    ~只測試與邊界值相關的輸入組合#全成對測試不專注於邊界，而是組合。
    ~為每個輸入變數定義一個獨特的測試案例#這無法涵蓋變數之間的交互作用。
}

::BlackBox_Advanced_05::「單一錯誤假設」（Single Fault Assumption）在測試案例設計中意味著什麼？{
    =假設錯誤只發生在單一變數（或單一等價區）的特定值上，其他變數則設定為有效或預設值#單一錯誤假設通常用於弱涵蓋，假設大多數錯誤是由一個不正確的輸入引起的。
    ~假設所有變數的錯誤會同時發生#這是多重錯誤假設。
    ~假設程式碼中只有一個錯誤存在#錯誤數量與此假設無關。
    ~測試案例的設計必須涵蓋所有邊界值的組合#這通常與邊界測試結合。
}

::BlackBox_Advanced_06::相較於單一錯誤假設，採用「非單一錯誤假設」（Multiple Fault Assumption）會如何影響測試案例的設計和數量？{
    ~測試案例數量會減少，但錯誤發現率降低#數量會增加。
    =測試案例數量會顯著增加，因為需要涵蓋多個輸入變數之間相互作用導致的潛在缺陷#非單一錯誤假設要求測試多個變數的錯誤組合，以找出交互作用引起的錯誤。
    ~只測試變數的有效等價區#應同時測試有效區和無效區的組合。
    ~僅限於白箱測試的使用#這是黑箱測試中的錯誤模型。
}


::BlackBox_Advanced_08::在一個安全性要求極高的軟體模組中，為了確保輸入參數的交互作用不會引發安全漏洞，測試經理決定採用哪種等價分割涵蓋強度？{
    ~弱涵蓋（Weak Coverage）#弱涵蓋專注於單一錯誤，可能錯過安全漏洞。
    =強涵蓋（Strong Coverage）或全成對（All-Pairs）#這兩種方法都涵蓋了變數之間的組合，特別是高風險模組需要使用強涵蓋來測試多重錯誤假設。
    ~隨機涵蓋（Random Coverage）#隨機性不能保證高風險組合被測試。
    ~邊界測試（Boundary Testing）#邊界測試專注於邊緣值，而非多變數交互作用。
}

::BlackBox_Advanced_09::一個使用者年齡輸入欄位要求年齡範圍必須在 18 歲到 65 歲之間（包含）。根據三點邊界測試策略，需要測試的無效邊界值應該是哪兩個？{
    =17 歲和 66 歲 #此策略要求測試剛好落在有效範圍之外的無效值，即 18-1=17 和 65+1=66。
    ~0 歲和 100 歲 #這兩個值是極端值，但不一定是緊鄰邊界的測試點。
    ~18 歲和 65 歲 #這是有效邊界值。
    ~17 歲和 18 歲 #18 歲是有效邊界。
}

::BlackBox_Advanced_10::測試人員在使用等價分割時，對於一個有效的等價區和相鄰的無效等價區，應該優先結合使用哪種技術以提高錯誤發現率？{
    =結合邊界值分析，因為邊界值通常位於等價區的邊緣#等價分割找出分區，邊界值分析則專注於分區的邊緣，兩者結合能以最少案例覆蓋最大風險。
    ~結合猴子測試，以隨機點擊的方式執行#猴子測試是另一種測試方法，與設計技術無關。
    ~結合全成對測試，以減少案例數量#全成對測試用於多變數，不直接用於單一等價區的邊緣。
    ~只使用弱涵蓋，完全不理會邊界#這會錯過最常見的邊界錯誤。
}

::BlackBox_Advanced_13::依賴於「單一錯誤假設」進行測試的主要風險或限制是什麼？{
    =無法有效發現由兩個或更多獨立的有效輸入（或邊界值）意外組合在一起所導致的交互作用錯誤#單一錯誤假設忽略了變數之間的複雜交互作用（多重錯誤）。
    ~測試案例的數量會過多，導致測試時間延長#單一錯誤假設的測試案例數量較少。
    ~無法測試到輸入範圍的邊界值#邊界值通常會被單獨測試。
    ~只能適用於黑箱測試#這是黑箱測試中的模型。
}

::BlackBox_Advanced_14::在三點邊界測試策略中，測試「max-1」（最大有效值減一）和「max+1」（最小無效值）的主要理由是什麼？{
    =程式設計師最容易在邊界條件處犯下「差一錯誤」（Off-by-one error）。
    ~測試案例的數量必須是奇數#數量與測試有效性無關。
    ~它們是所有等價分割的代表值#等價分割的代表值通常選在區間內，而非邊界。
    ~它們是隨機產生的輸入值#邊界測試是系統性設計，而非隨機。
}

::BlackBox_Advanced_15::在產品的 Beta 測試階段，測試經理通常會要求外部使用者提供「非單一錯誤假設」的輸入。這是因為什麼？{
    =外部使用者在真實情境中產生的隨機和非預期組合輸入，更有可能觸發多變數交互作用導致的錯誤#外部使用者並不遵循單一錯誤假設，他們更可能輸入奇怪的、多重組合的錯誤，這正是多重錯誤假設所涵蓋的範圍。
    ~外部使用者可以提供程式碼覆蓋率的數據#程式碼覆蓋率是白箱測試指標。
    ~非單一錯誤假設可以降低測試案例數量#非單一錯誤假設會增加測試案例數量。
    ~Beta 測試是弱涵蓋的最佳時機#Beta 測試應是高強度、高涵蓋的測試。
}
